# Reference implementation and gold standard

The point of a port is fidelity. You cannot claim it without a frozen target from
the original implementation to match. This file covers finding the reference,
the licensing rules for reading its code, and capturing the gold-standard fixture.

## Find the reference implementation

In rough order of authority:

1. The implementation released by the paper's authors (linked from the paper or its
   project page) — the canonical reference.
2. A widely-used package that implements the method (an R/CRAN package, a Python
   package, a C++ library such as MALLET or tomotopy).
3. A faithful third-party reimplementation, only if 1–2 do not exist, and note its
   provenance.

Record in the spec note: the reference's name, version, URL, and license.

## Licensing: read the code only when legal

**Check the license before reading the reference's source to match algorithmic
detail.** This protects the project's own license.

- **Permissive (MIT, BSD, Apache-2.0)**: you may read the code to match details
  (initialization, update order, hyperparameter defaults, numerical guards). Do not
  copy substantial verbatim blocks; reimplement in idiomatic Rust. Credit the
  reference in the model's docstring and the docs.
- **Copyleft (GPL, AGPL, LGPL) or no clear license**: do NOT read the source to
  copy logic, and do not vendor any of it. Implement from the **paper** and treat
  the reference as a **black box** — you may still run it and compare outputs, which
  is the gold-standard step below. State in the spec note and PR that the port is
  paper-derived and the reference was used only as a black-box oracle.

When unsure, assume the stricter path (black box). topica credits its references
explicitly (see the README acknowledgements); follow that pattern.

## Capture the gold-standard result set

Goal: a small, fixed, reproducible set of reference outputs checked into `parity/`
(or referenced from it) that the topica port must reproduce within tolerance.

1. Build a small synthetic corpus with a fixed seed and a planted structure (so the
   "right" answer is known) — e.g. two or three well-separated word blocks. Keep it
   small enough to fit in seconds in both engines.
2. Run the reference on that exact corpus, with a fixed seed and a fixed,
   documented configuration (K, iterations, priors). Save: `topic_word`,
   `doc_topic`, any model-specific diagnostic, and the full settings + seed.
3. Store the captured arrays where the parity check can load them. Mirror how
   existing parity fixtures are stored (some are committed golden files, some are
   regenerated by the script when the tool is present). Prefer a committed golden
   file when the reference is slow or not always installed.

Note that most methods are stochastic, so exact equality across implementations is
usually impossible (different RNG, different update order). The realistic target is
**topic-aligned similarity**: align topica's topics to the reference's (Hungarian
assignment on the topic-word matrices), then require high per-topic cosine and
recovery of the planted structure. `scripts/compare_to_reference.py` does this.
Calibrate the bar against the reference's own seed-to-seed variation — two runs of
the reference with different seeds set the noise floor; the port should land within
that floor, not below it.

**Two model properties change the bar. Decide both up front and write them into the
spec note:**

1. **Is the reference initialization deterministic?** If so (e.g. NMF with NNDSVDa,
   any SVD/anchor-word init), the seed-to-seed floor is *degenerate* — zero variance
   — and "land within the floor" silently collapses to "must equal 1.0000 exactly,"
   which will flag even a 4e-5 difference as a failure. That happened porting NMF.
   Calibrate instead against an **init-perturbation floor**: run the reference with
   `init="random"` (or jitter the deterministic init) across seeds and use that
   spread as the noise floor.

2. **Does the model match a *solution* or only an *objective*?** Non-convex /
   non-identified models (NMF, and many LDA-ish models) have multiple equal-quality
   optima, so topic-aligned cosine ~1 is the **wrong** bar — topica can find an
   alternate factorization of equal or better quality at cosine ~0.86 (NMF at K=20
   on poliblog5k did exactly this). For these, the bar is **objective parity**
   (reconstruction loss / held-out likelihood within tolerance, plus planted-structure
   recovery), not reproducing the reference's specific decomposition. Reserve the
   "match the exact decomposition (cosine ~1)" bar for convex / identified methods.

## The `parity/` pattern

`parity/` holds cross-implementation checks against R (`stm`, `keyATM`) and Java
MALLET. A new model's parity check should:

- Detect the reference tool (e.g. `Rscript` with the package, a Python import, a
  binary on PATH) and **skip cleanly** with an informative message when it is
  absent — CI and contributors without the tool must still pass.
- Re-run the reference (or load the committed golden file), run topica on the same
  corpus, align, score, and assert the similarity bar.
- Document the configuration inline so the comparison is reproducible.

Read the existing `parity/` scripts before writing a new one and match their shape.
